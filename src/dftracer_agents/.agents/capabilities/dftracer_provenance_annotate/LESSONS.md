# Lessons: dftracer_provenance_annotate

- [L-3887355f] An entity's store/uri in the graph came from the wrong call site -> the first declaration of an entity in a process wins (its store and uri come from the first used/generated/entity call; later calls only add edges) -> declare with the full store/uri the first time, or call prov.entity up front (2026-10-01)
- [L-e47e53c8] Deletes and in-place changes showed up as extra activities -> the wrong relation was used -> deletes are `invalidated`, in-place modification is `updated`; containment/versioning are entity relations (`contains`, `revision_of`), not extra activities (2026-10-01)
- [L-1dffcde3] Activity args missing from the trace -> dftracer's JSON serializer used to drop ALL event args without DFTRACER_INC_METADATA -> run with DFTRACER_INC_METADATA=1; the entity API keeps relation args regardless (serializer fix on the API branch) (2026-10-01)
- [L-426552b1] A worker's edges vanished and showed up as dangling_hashes; a one-activity smoke check wrote NO trace file -> STDIOWriter::finalize unlinks the trace when the process logged fewer than 5 data events (dftracer's own start/end count) -> log >= 3 activities when testing; do not suspect a broken install (2026-10-01)
- [L-90f3b35a] Python process-pool workers and spawned servers produced no provenance -> children leave via os._exit and skip atexit -> register finalize with both atexit.register(fini) and multiprocessing.util.Finalize(None, fini, exitpriority=100); init once per pid in the pool initializer (executor_worker_init style) and the server's startup (2026-10-01)
- [L-b7c98c2d] Pool tasks broke after wrapping them -> pool tasks are pickled by name -> rename f to _f_impl and keep a same-named wrapper that opens the activity; diffs stay small (2026-10-01)
- [L-e45de43d] RPC/subprocess edges missing on the driver side -> the framework runs the task, not the app -> subclass the task type (ServerTask.start, SubprocessTask.on_finish) to record the driver side; record the server side in the request handler with the identical type+id (2026-10-01)
- [L-b7e4577a] provenance_install_helpers(include_into=...) put the import inside a multi-line import -> line-based insert -> it is AST-based now and inserts after the whole import; provenance_validate skips the helper files' own docstring examples (2026-10-01)
- [L-8b0ec987] C/C++ provenance run exits 0 but the trace is 0 bytes and the graph empty -> dft_prov_* calls only record once dftracer is initialized; no DFTRACER_C_INIT/DFTRACER_CPP_INIT -> provenance_ensure_lifecycle on the file that defines main() (INIT first statement, FINI via atexit); provenance_validate fails until it is done (2026-10-01)
