# Lessons: dftracer_optimize_io

- [L-db877ade] ScaFFold on Tuolumne showed critical posix_*_ops_slope bottlenecks and only ~41% compute/I-O overlap despite L1-optimal DataLoader settings -> the fractal dataset sat on an NFS workspace (single server, no striping, hard bandwidth/IOPS cap) -> copy the dataset to Lustre with matched striping and repoint the data dir; check `stat -f`/`df -T` before any benchmark (2026-07-10)
- [L-b8f69391] Optimizer proposed flipping MEM_PATTERN/FILE_PATTERN INTERLEAVED->CONTIG or larger transfer sizes because they measured faster -> that changes the workload's access pattern (not a system optimization, can break correctness) -> keep the real pattern and request size; serve it faster with buffering, caching, prefetching, stage-in, collective buffering, layout (2026-07-10)
- [L-eae095bd] Optimizer stopped at the top bottleneck's obvious fix -> no exhaustive walk of the dimension checklist -> walk all 12 dimensions every session, verdict for each, literature search before 'not applicable' (2026-07-10)
- [L-a8f351d0] vpic-kokkos benchmark.cxx at 128 ranks: 340.85M POSIX ops moved 325.0 MB in 1.65 s of a 210.2 s job and a striping/ROMIO fix was considered -> the I/O was op-count-bound and structurally negligible; ROMIO/striping target bandwidth-bound patterns -> check I/O share of job time and few-huge vs many-tiny ops first; only app-level write coalescing helps op-count-bound I/O (2026-07-14)
- [L-e494f1c7] 2-node Ray Train run showed huge metadata op counts (117,920 __lxstat64) and a metadata-layer fix was considered -> the ops were venv/site-packages import traffic (dynamic loading), the dataset file was 9 ops / 0.006 s -> resolve FH records to paths and report import traffic (Spindle-class fix) separately from application data (2026-07-14)
- [L-dfd65ff1] IOR 4.0.0 / HDF5 1.14.5 on Tuolumne: untraced optimization variants looked ~60% faster than the baseline -> the baseline had DFTRACER_ENABLE=1 (FUNCTION-mode tracing cost ~37% of write bandwidth at 4 KiB transfers) -> grep both arms' launch scripts for DFTRACER_ENABLE/DFTRACER_INIT, refuse mismatched comparisons, report headline bandwidth from untraced runs (2026-07-24)
- [L-b864fe48] Two back-to-back same-night Lustre campaigns differed ~11%, larger than most effects under test -> filesystem/cache state drift and back-to-back-by-arm ordering -> fresh unused output directory per replicate, interleave arms (v0, v1, v0, v1), claim a delta only when its range does not overlap the baseline's (2026-07-24)
- [L-02993d53] 1000genome individuals.py: many-small-file producer followed by tarfile.add(dir) doubled the effective op count -> archiving re-touches every just-written file (open+stat+read+close per member) -> stream members into the open TarFile (tarfile.addfile(TarInfo, BytesIO)); IND_TAR_STREAM=1 measured -13.2% standalone and its share grew after the compute fix (2026-07-26)
- [L-4c33674e] romio_ds_write=disable caused a 4x write regression -> applied on VAST NVMe, where it is harmful (safe only on Lustre spinning disk) -> confirm the detected FS_TYPE and only propose L3/L2 strategies valid for it (2026-07-10)
- [L-97c26be6] Small-file ML dataset striped with a high stripe count 'for safety' was slower -> striping a tiny file across OSTs adds overhead, parallelism comes from many files -> lfs setstripe -c 1 on the dataset directory before copying data in; verify with lfs getstripe (2026-07-10)
- [L-beb549e4] Flash-X: ROMIO hints bought only 18% -> one rank still wrote 91% of the bytes (single-writer funnel in the app) -> apply L1 before L2/L3; 7.6x arrived only after the L1 rebuild (2026-07-10)
- [L-6f930d15] Parallel io and compute optimizer dispatches on the same annotated/source tree crashed a DDP run twice (NCCL 'remote process exited') -> a sibling's concurrent edit desynced ranks mid-run -> know file ownership, pin sibling env-gates (e.g. PECAN_TORCH_COMPILE) off in your run script, check for diffs in files you did not touch before blaming your change (2026-07-22)
