# Lessons: dftracer_optimize_communication

- [L-d4f8b4b0] vpic-kokkos: diagnosed MPI_Allreduce cost (three small per-timestep reductions, coalescible into one) -> the reductions live inside libvpic.a, not the input deck or a runtime flag, so the fix needs an incremental library relink -> weigh the rebuild against the remaining allocation; report patch + citation as a high-confidence, explicitly unmeasured candidate and defer the measured trial to a dedicated validation step rather than fabricate a result (2026-07-14)
- [L-6d2af31e] PECAN/PDBspheres: Layer Breakdown showed zero events for communication-except-io (cpu-gpu-transfer) -> the category fired (3264 events, 25.58 s over 16 ranks x 2 epochs) but was ~15,000:1 smaller than 50.5M cat=hdf5 events and rounded to invisible -> before reporting a category as zero, count events and sum dur for its literal cat through the trace tools (event_count/view/reader or TraceViewer) (2026-07-20)
- [L-ee4d1154] PyTorch DDP with DFTRACER_ENABLE_HIP_TRACING=OFF: no RCCL/NCCL allreduce time in the trace -> DDP fuses gradient allreduce into loss.backward() via bucket-ready hooks, so it is folded into the compute/model-backward context -> flag it as an open coverage gap (needs HIP-level or rocprof/RCCL tracing), never assume zero comm cost (2026-07-20)
- [L-a32cba01] PECAN 16-rank EGNN/PyG DDP: communication tempting to optimize -> cpu-gpu-transfer cost 25.58 s aggregate (~2.6% of the 961 s I/O bottleneck, <1% of wall), DDP overlap and pin_memory=True already default, coalescing .to(device) calls has <1% ceiling -> check the diagnosed severity ranking before spending budget on a lower-ranked dimension (2026-07-20)
- [L-95e841fb] 1000genome-workflow / Pegasus PMC: zero MPI_* spans in any trace although task dispatch is MPI -> the scheduler binary pegasus-mpi-cluster is not dftracer-annotated, a structural blind spot -> use the scheduler's own [cluster-summary ... bytes_sent=<N>] line as ground truth (29,956 bytes over 316.5 s / 32 ranks, 0.0002% of run time) and state the coverage gap (2026-07-26)
- [L-a7c4dfb9] 1000genome-workflow DAG: 19.4% worker utilization looked like a rank-count lever -> 8-level DAG with max width 17 (individuals fan-out) vs 31 workers, so the pool is never the binding constraint -> compute DAG level widths from the .dag TASK/EDGE structure before proposing any worker-pool/rank-count change (2026-07-26)
- [L-31f0570a] ray_molformer (4 nodes / 16 GPUs, Ray Train DDP over RCCL, HIP tracing ON): communication under-counted, compute over-counted -> RCCL device kernels appear as cat=KERNEL_DISPATCH named <n>_Z21ncclDevKern... and the Layer Breakdown attributes them to compute (541.7 s = 95.4% of the 568.0 s KERNEL_DISPATCH bucket; the comm category's 306.9 s was Ray control plane, ~2.8x undercount) -> select ncclDevKern kernel-dispatch events and subtract them from compute before ranking dimensions (2026-08-02)
- [L-decbc792] ray_molformer: NCCL_ALGO/NCCL_PROTO tuning considered for slow collectives -> collective kernel durations were bimodal (p50 ~80 ms, max 8.5 s; 87% of collective time in the slow tail): rank/straggler skew, not bandwidth -> if < ~20% of collective time is in sub-200 ms kernels, balance per-rank work (balanced sharding, drop_last=True) instead; cite arXiv:2505.23523 (2026-08-02)
- [L-baee143c] parallel component optimizers on the same annotated/source tree: NCCL "remote process exited" crash, twice in one session -> a sibling optimizer edited a file the multi-rank job was loading, desyncing ranks -> know your own files, pin the sibling's env-var gates (e.g. PECAN_TORCH_COMPILE) to the safe value in your run script, and diff untouched files before blaming your own change (2026-07-20)
