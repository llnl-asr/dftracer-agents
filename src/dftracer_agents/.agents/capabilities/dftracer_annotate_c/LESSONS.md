# Lessons: dftracer_annotate_c

- [L-d464e0ad] DFTRACER_C_INIT(NULL, NULL, -1) causes segfault — third arg must be NULL not -1 (error: Segmentation fault in initialize_main() at fgets call immediately after startup. Stack: main → read_config_from_file → fgets → SIGSEGV) -> DFTRACER_C_INIT macro passes its third argument directly to initialize_main(log, dirs, int *process_id). Passing the integer -1 is implicitly cast to (int*)0xffffffffffffffff, which initialize_main then dereferences → immediate segfault. -> Always use NULL (not -1 or any integer) for the process_id argument: DFTRACER_C_INIT(NULL, NULL, NULL) NULL is a valid int* meaning "auto-detect PID". The pipeline skill init_args default was updated from "NULL, NULL, -1" to "NULL, NULL, NULL". (2026-06-20; app: https://github.com/hariharan-devarajan/h5bench (main); tags: [c, dftracer-init, segfault, init-args, pipeline-skill])
- [L-d65559e2] Inserting DFTRACER_C_FUNCTION_END into braceless single-line if (dryRun pattern) (error: Inserting END made the early return unconditional — dryRun check bypassed. Or: compiler error "expected ';' before DFTRACER_C_FUNCTION_END") -> C braceless-if shares its body with the first following statement. END inserted before the return stole the if body, making return fall through always. -> Grep for braceless early-exit lines before annotating each file: grep -n "if.*return\|if.*continue\|if.*break" <file.c> | grep -v "{" | grep -v "//" For each hit, add explicit braces FIRST, then insert END: // Before: if (dryRun) return NULL; // After: if (dryRun) { DFTRACER_C_FUNCTION_END(); return NULL; } (2026-06-17; app: https://github.com/llnl/ior (tag 4.0.0); tags: [c, annotation, braceless, if-body, dryRun, build-error])
- [L-d74cc51e] DFTRACER_C_FINI placed before ior_main() call — all backend spans missing from trace (error: Trace contains only the main() span. No POSIX_Create, MPIIO_Open, HDF5_Close or any other backend spans appear even though those functions are annotated.) -> DFTRACER_C_FINI() was placed just before the final return in main(), BEFORE ior_main() had been called. dftracer finalized and stopped recording; all backend I/O that ran inside ior_main() was untraced. -> FINI must appear AFTER the top-level benchmark function returns. Structure: int main(...) { MPI_Init(...); DFTRACER_C_INIT(NULL, NULL, NULL); DFTRACER_C_FUNCTION_START(); ... ior_main(opts); // ← real I/O happens here DFTRACER_C_FUNCTION_END(); DFTRACER_C_FINI(); // ← AFTER ior_main, not before the benchmark call MPI_Finalize(); return 0; } Before placing FINI, identify the "benchmark call" in main() — the call that does all the real work — and ensure FINI comes after it returns. (2026-06-17; app: https://github.com/llnl/ior (tag 4.0.0); tags: [c, annotation, fini, main, empty-trace, benchmark-wrapper])
- [L-8fa408e5] HDF5 stray END inserted because grep matched forward declaration instead of definition (error: HDF5_Create had a DFTRACER_C_FUNCTION_END() inserted before DFTRACER_C_FUNCTION_START() — compile error or incorrect trace span.) -> grep matched the forward declaration of HDF5_Create (which ends with ';') and inserted an END there, then also annotated the real definition. -> Always filter grep results to definitions only: grep -n "HDF5_Create" file.c | grep -v ";$" The definition has a body ({...}); the forward declaration ends with ';'.
